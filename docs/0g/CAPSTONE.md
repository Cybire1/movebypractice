# Capstone

HURU v2 — the Verifiable Memory Rail. Not a new product; the existing Huru gateway extended until every 0G layer is load-bearing, with the fiat and custody layer that 0G has no roadmap for kept as the moat.

WHAT IT IS, LAYER BY LAYER. Compute: Huru gains a Router-backed transport alongside its Direct transport, adopts the X-0G-Provider-* header vocabulary verbatim, emits a spec-shaped x_0g_trace, and implements the sk-/mk- scoped key model with the create/manage split — so it is a drop-in-compatible superset of the 0G Router rather than a competing dialect. It keeps the Direct path for the one thing the Router cannot serve: a LoRA adapter fine-tuned on Nigerian-English and pidgin support traffic (lesson 15). Per-call verification comes from processResponse's actual return value, with verifyService attestation cached per provider and labelled with its true scope (two automated checks of four). Storage: memory is 0gmem with a 0G Storage backend (lesson 28) — encrypted graph snapshots, a KV hot pointer, per-consumer envelope encryption under HD-derived keys — and every read is Merkle-verified by recompute-and-compare, because the SDK's proof flag does not work. Chain: Chum is registered in the ERC-8004 Identity Registry and cross-linked to its ERC-7857 iNFT; Huru's daily TEE pass-rates land in the Validation Registry as tagged validationResponses, making per-call attestation a durable on-chain track record instead of a UI panel; the iNFT gets a real TEE re-encryption oracle so agents become genuinely sellable (lesson 27). DA: nightly memory-graph checkpoints are dispersed to 0G DA, and a DAGated contract accepts a checkpoint only when the DASigners quorum bitmap clears a two-thirds threshold — so a user can prove their agent's memory at a point in time was published, not merely that Huru says so. DePIN: Huru operates its own 0G storage node and DA client, making it supply as well as demand. Read path: a Goldsky subgraph, so the on-chain half of every proof is reproducible by a stranger with a query URL.

WHY IT IS FUNDABLE. The Router commoditises the gateway layer Huru currently occupies — that is the uncomfortable truth Afeez must say first, before anyone says it to him. Huru's defensible ground is not OpenAI compatibility; it is fiat rails (Naira and USD via Paystack from about 100 naira), per-consumer HD wallets giving each end user their own custody boundary, and West African distribution. None of those appear on the Router's roadmap, and its per-key spending controls are explicitly "coming soon". So the play is composition, not competition: route TEE traffic through 0G's Router, keep the wallet and fiat layer on top. In exchange 0G gets three reference implementations it does not currently have — the first production consumer of 0gmem backed by 0G Storage (closing a gap in 0G's own repo), the first ERC-8004 Validation Registry integration on 0G, and the first agent product anchoring memory checkpoints to 0G DA with on-chain quorum gating — plus a market where 0G has no presence and a distribution channel (MoveByPractice's public 0G track) that recruits developers into the same stack. It exercises compute, storage, KV, chain, agentic identity, DA, precompiles, indexing and node operation, which is exactly the demonstration DevRel asked for, delivered as a shipping product rather than a exercise set.

# Evidence plan for 0G DevRel

1. 1. LEAD WITH THE CORRECTION, UNPROMPTED. Open with 'processResponse stopped being a payment primitive and became a verification primitive — billing moved to provider-side delayed batch settlement, the signature dropped to two arguments, and every local SKILL.md still says otherwise.' Then show the diff in runtime.ts where Huru's badge stopped being a self-reported provider string and started being that return value. Leading with a fix to your own strongest claim is the highest-trust opening available, and it inoculates you against the finding rather than waiting to be caught by it.
2. 2. THE HONESTY LEDGER. A one-page STACK_STATUS.md in the Huru repo listing every claim as ENFORCED, PARTIAL or MOCK, with the artefact that proves each. It must name the two things that were wrong — the withProof=false read path and the mock ERC-7857 verifier — with the commit or tx hash that fixed each. Say it before they find it. This is the single document that converts a hackathon impression into an engineering one.
3. 3. ONE REQUEST, END TO END, ON ONE SCREEN. Take a single live Chum request and walk the entire proof chain: request_id → provider on-chain address → x_0g_trace billing in neuron → processResponse verdict → cached verifyService scope → storage root hash → recomputed root matching → the ERC-8004 validationResponse tx that recorded it. Then verify the same request independently in front of them using a throwaway wallet, proving they do not have to trust your API. That demo is the whole thesis in ninety seconds.
4. 4. THE PUBLIC 0G TRACK ON MOVEBYPRACTICE. Beginner tier live and playable by a stranger with a faucet, lessons authored against packages/shared/types/lesson.ts with real Teaching / Quiz / Practice phases and the interactive components already in the platform — DragDrop for chunk→segment→root and for the six-step 7857 transfer, ClickReveal for trust-tier→guarantee→failure-mode, CodeHighlight built from the two real bugs in 0G's own starter kit (startup.ts's 0.01 below the 3 0G minimum, demo-compute-flow.ts:220's wrong third argument). This is the artefact that serves 0G's developer adoption rather than just your own credibility.
5. 5. DA, THE LAYER YOU HAD NEVER TOUCHED. Show the offline data-root computation first (proving you understand the construction rather than just running a binary), then the dispersed blob whose root matches it, then the DAGated accept/revert transaction pair. Sequencing matters here: computing the root without a node is the part that reads as comprehension.
6. 6. THE ROLLUP. An OP Stack devnet posting batches to your own 0G DA client — L2 tx, L1 batcher tx, data root, retrieved blob containing the L2 bytes. Then the Arbitrum Nitro work and the PR against 0gfoundation/0g-doc closing the gap that page currently has. Frame it explicitly as the same move as the merged storage-SDK fix, at higher stakes.
7. 7. NODE OPERATION. Your storage node's zgs_getShardConfig, a zgs_getFileInfo showing your own root hash finalized on your own node, and your DA client. This is the only evidence they can verify independently by looking you up in the network, and it closes 'has he only ever been a client?'
8. 8. THE 0GMEM PR. A 0gmem instance restored from nothing but a root hash and a KV pointer after a container wipe, with a matching LoCoMo score. Present it as closing a gap in 0G's own repository, not as a Huru feature.
9. 9. THE COMPARISON MEMO AND THE ASK. COMPARISON.md, three columns: Router only / both / Huru only. Concede openly that the Router commoditises the gateway layer, then make the composition case — fiat rails, per-consumer custody, Africa distribution, Huru routing through the Router rather than around it. End on the funding ask, framed as the three reference implementations 0G gets in return. Do not bury this; it is the conversation they want to have, and going into it having already conceded the weak point is what makes the ask credible.
